# 实验一 环境搭建与验证记录

> 本文是实际搭建过程的记录，数据均来自本机实测，可直接用于实验报告的“五、实验代码运行与调试”。

## 一、实验目的

1. 完成 JDK、Maven、MySQL、IDEA 的安装与配置，能独立判断环境是否可用。
2. 掌握 Java 环境变量（`JAVA_HOME`、`Path`）与 Maven 本地仓库、镜像源的作用。
3. 掌握 Git 仓库初始化与分支规范。
4. 创建 Spring Boot 项目，开发基础 Controller 接口并在本地访问成功。

## 二、实验设备

软件：

- 操作系统：Windows 11（64 位）
- JDK：Eclipse Temurin 17.0.20.1（`D:\dev\jdk17`）
- Maven：Apache Maven 3.9.16（`D:\dev\maven`）
- Git：2.56.0.windows.4（`D:\dev\Git`）
- MySQL：8.0（Windows 服务 `MySQL80`，端口 3306）
- 数据库客户端：MySQL Workbench 8.0 CE
- 构建产物：`medical-system-0.0.1-SNAPSHOT.jar`（23 MB）

硬件：

- 处理器：x64（amd64）
- 内存与磁盘：JDK、Maven、Git 三套件合计占用约 1 GB，工程目录约 30 MB

说明：本机当前会话没有管理员权限，因此 JDK / Maven / Git 均采用免安装压缩包 + 用户级环境变量的方式部署，不写入系统目录。

## 三、实验原理及内容

1. JDK 提供 `javac` 编译与 `java` 运行能力，`JAVA_HOME` 是给 Maven、IDEA 定位 JDK 的约定变量，`Path` 让命令行直接调用 `java`、`javac`。
2. Maven 依据 `pom.xml` 中的坐标向远程仓库请求依赖，缓存在本地仓库，再完成编译、测试、打包。配置镜像可把默认的境外中央仓库换成阿里云，避免下载超时。
3. Spring Boot 通过 `@SpringBootApplication` 触发自动配置与内嵌 Tomcat，`@RestController` + `@GetMapping` 把方法映射为 HTTP 接口。
4. Git 通过分支隔离开发：`main` 保留可交付版本，`develop` 承载集成，`feature/*` 承载单个功能。

## 四、实验要求

1. 四个组件安装成功，命令行可验证版本。
2. Git 仓库完成初始化，具备 `main`、`develop` 分支，具备 `.gitignore`。
3. Spring Boot 项目可构建，可启动，至少一个接口返回正确结果。
4. 记录关键现象与运行结果。

## 六、实验总结

环境搭建的难点不在安装本身，而在版本之间的匹配与环境变量的生效顺序。本次遇到的三处问题都能说明这一点：

一是 MAT 安装包在无管理员权限的会话里返回 1925 错误，最终改用压缩包解压 + 用户级 `JAVA_HOME` 解决，也说明 `JAVA_HOME` 指向的是 JDK 根目录而不是 `bin`。

二是默认中央仓库下载超时，配置阿里云镜像与本地仓库后构建时间明显下降。

三是 Windows 默认平台编码为 GBK，编译含中文的源码时会出现乱码风险，通过 `MAVEN_OPTS=-Dfile.encoding=UTF-8` 与 `pom.xml` 中的 `sourceEncoding` 双重固定。

另外确认了一个容易被忽略的点：环境变量写入注册表后，已经打开的终端和 IDE 不会自动刷新，必须重开进程才能读到新值，否则会出现“明明配了却找不到 JDK”的假故障。
